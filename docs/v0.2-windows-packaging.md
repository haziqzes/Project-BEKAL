# BEKAL V0.2 — Windows Packaging

## Status

Complete. Owner-machine acceptance passed on 2026-10-15 with the corrected V0.2 installer.

## Objective

Turn the proven BEKAL V0.2 desktop shell into a normal Windows application that can be installed, launched from Windows shortcuts, upgraded, and uninstalled without requiring the user to browse the repository or use the legacy CMD launchers.

## Preserved behavior

- React remains the bundled desktop UI.
- FastAPI remains the local backend.
- PostgreSQL remains the local database.
- OCR remains local and free.
- The backend remains loopback-only on the host.
- Existing repository/Docker browser mode remains supported for development and recovery.
- Existing receipt and database data must survive normal application shutdown, upgrade, and uninstall unless the user explicitly removes local application data.

## Phase 3 scope

1. Build a Windows NSIS installer.
2. Use the product name `BEKAL` and executable name `BEKAL.exe`.
3. Set application metadata to BEKAL / Wan Haziq / MIT / Project-BEKAL.
4. Provide a BEKAL-specific application icon.
5. Provide Start Menu integration and the standard NSIS desktop-shortcut option.
6. Bundle a minimal Docker runtime template containing only the backend runtime files required by the installed application.
7. Materialize that template into the per-user Tauri local-data directory on first run.
8. Generate a private local `.env` on first run and never bundle or commit the generated file.
9. Continue to require Docker Desktop as the local container runtime; do not silently install or modify Docker Desktop.
10. Keep PostgreSQL unexposed to host TCP in the packaged runtime. FastAPI remains bound only to `127.0.0.1:8000`.
11. Sync managed runtime files on application upgrades without deleting receipts, PostgreSQL data, or the generated `.env`.
12. Build and audit the installer in GitHub Actions on Windows.
13. Complete an owner-machine install / launch / close / relaunch / uninstall acceptance test before merging and releasing V0.2.
14. Release builds must use the packaged per-user runtime even when launched from a shell whose current directory happens to be the source repository. Repository auto-discovery is limited to debug builds or an explicit `BEKAL_REPO_ROOT` override.

## Owner acceptance discovery

The first owner-machine installer run exposed an important runtime-isolation edge case. The installed release executable was launched from a PowerShell session whose current directory was the Project-BEKAL source checkout. The initial release resolver searched that current directory before preparing the packaged runtime, so the installed application attached to the development Compose stack instead of its own `bekal-desktop` stack.

This was treated as a product defect rather than worked around in the acceptance script. Release builds now ignore incidental repository working directories and always use the installed per-user runtime unless `BEKAL_REPO_ROOT` is explicitly supplied. Debug builds retain convenient repository auto-discovery.

## Non-Goals

- Replacing Docker/PostgreSQL with an embedded database.
- Bundling or automatically installing Docker Desktop.
- Cloud sync or cloud hosting.
- Authentication or multi-user support.
- Auto-update infrastructure.
- Microsoft Store packaging.
- macOS or Linux installers.
- Recipes, pantry, budgeting, HANA integration, mobile, or unrelated product features.

## Runtime layout

The installer contains a read-only runtime template as a Tauri resource. On installed startup BEKAL copies/synchronizes the managed template into its per-user local-data directory. The writable runtime contains:

```text
<app-local-data>/runtime/
├── .env                 # generated locally, private, preserved
├── docker-compose.yml   # managed by BEKAL
├── backend/             # managed by BEKAL
└── runtime-data/        # private receipts/candidates, preserved
```

PostgreSQL data remains in the stable Docker named volume for the desktop Compose project.

## Installer policy

- Bundle target: NSIS.
- Install mode: per-user, avoiding administrator elevation for normal installation.
- Start Menu folder: BEKAL.
- Desktop shortcut: standard NSIS user choice.
- WebView2: Tauri bootstrapper behavior.
- Publisher: Wan Haziq.
- Identifier: `com.haziqzes.bekal`.
